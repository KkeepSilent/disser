## Вход

Логин проверяется через `authenticate_app_user`. Функция нормализует имя и сравнивает результат `pgcrypto.crypt` с сохранённым bcrypt. Для отсутствующего пользователя рассчитывается bcrypt с фиксированной солью. API выдаёт одинаковое сообщение для неверного логина и пароля. Стандартный демосид создаёт `edu` с паролем `123`. [supabase/seed-editor.sql](../supabase/seed-editor.sql)

## Сессия

Сервер генерирует случайный токен из 32 байтов. Cookie `trademind_session` содержит токен, в БД хранится SHA-256. Атрибуты cookie: HttpOnly, SameSite=Lax, Path=/, Secure в production. Cookie и запись создаются на семь дней. SSR проверяет сессию, а API может продлить её. Выход удаляет запись и очищает cookie. [src/lib/server/auth.ts](../src/lib/server/auth.ts)

## Роли

| Роль | Права |
|---|---|
| user | Свой симулятор и журнал |
| admin | Те же права, плюс список, создание, редактирование и удаление пользователей |

Администратор не может удалить себя или снять с себя роль. RPC проверяет владение сделками и сессиями там, где выполняет операции над ними. Привилегированный ключ хранится на сервере. [База](database.md#доступ-и-миграции).

## Известные ограничения

- Используйте другой пароль для публичного окружения. [ТЗ 1A.8](../TZ-FIX-BUGS.md)
- В текущем коде порог продления равен шести значениям TTL, то есть 42 дням. Для семидневной сессии он обычно истинный, поэтому проверка API может выполнять лишний UPDATE. [ТЗ 2B.2 и 2C.8](../TZ-FIX-BUGS.md)
